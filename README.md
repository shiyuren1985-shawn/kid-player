# 小小影院 · Android 原型

项目统一位置：`/Users/shawn/AI/KidPlayer`。源码、调试 APK、启动脚本、开发辅助文件和素材/检查记录均在此目录内。Android Studio、Android SDK、JDK 和模拟器镜像仍使用系统级安装位置，不跟随项目搬迁。

用于观看家长指定范围的视频。一个 APK 包含触控平板布局与电视遥控器布局，保留本地演示与 SMB，并新增实验性 B 站指定 UP 主订阅。

## 0.3 可用的公开合集自动同步（2026-09-04）

当前版本已在 Android 12 专用模拟器完成真实联网同步：从“画渣花小烙”（UID 402576555）的 6 个公开合集读取 184 条视频记录，再单独通过视频详情接口核验作者和公开状态，保留最新 30 条。成功时间写入目录，不再依靠打包的 3 条初始链接。只读取元数据，播放仍直连平台正常返回的音视频流，不下载整部视频归档。

**范围是“公开合集中的视频”，不是“该 UP 主的全部投稿”。未加入合集的新投稿可能遗漏。** 合集已包含本轮主页最新的三条投稿，但这不能证明以后每条都会进入合集。界面在目录、首页与设置中明确标注范围；旧的完整投稿 API 仍受 -352 限制，没有把该限制伪装成已解决。

- 启动/返回时检查，前台每 15 分钟检查，后台由 WorkManager 在有网络时按周期调度；系统省电或强行停止可能延后，不是实时推送。
- 先读取该作者公开合集的所有分页，再去重、按发布日期排序。逐条核验视频的 `owner.mid`，合集里即使放入其他作者的视频也不会加入孩子的目录。
- 最多扫描 20 个合集、500 条合集记录；分页不完整、目录读取中变化、出现不支持的列表类型或平台拒绝时，整次失败并保留上次成功目录，不冒充完整更新。
- 每次只展示核验后的最新 30 条，不是完整历史；喜欢和继续观看不扩大当前目录。
- 请求间隔至少 150ms，有同步总时限和手动请求冷却；不用浏览器登录凭据，不模拟设备指纹，不处理验证码，不使用第三方解析站。
- 同步成功不表示内容经过家长逐条审核。它是作者/来源白名单，不是视频内容识别系统；无弹幕、无评论指不加载平台附加界面，不删改原视频中的内容。

同步实现见 `BiliCollections.java`，检查记录见 `qa/collections-0.3.md`。下面的 0.2 记录保留为历史，不代表当前只能播放三个视频。

0.3 验证：13 项单元测试、22 项模拟器集成测试全部通过（共 35 项），Lint 0 错误、23 项警告，调试 APK 签名校验通过。新增测试验证分页扫描、核验作者、更新时加入新条目、冷却和失败保留旧目录；新条目测试为模拟接口事件，不代表已经等待该作者未来真实发布。

## 0.2 在线订阅原型（历史记录）

点击左侧“UP 主订阅”，订阅用户提供的 UID `402576555`。来源在 `BiliPolicy.java` 固定，应用内不提供修改 UID、搜索、粘贴视频链接、推荐、评论、弹幕或打开外部网页的入口。保持原来的爱心萌可图标和无 PIN 设计。

**自动同步仍受限：** 本轮 Mac 的投稿接口实测返回 -403 / -352；带常规 WBI 签名的投稿请求返回 -352（风控校验失败）。但正常 Chrome 可以加载该作者主页，视频详情和播放资源接口成功返回。主线程没有读取或导出浏览器 Cookie，没有绕过登录或验证码，也不调用第三方解析站。

初始目录包含正常主页最新显示的 3 条真实投稿：汗疱疹、蚊子读评论、游隼。每条都另行通过详情接口核验 `owner.mid=402576555`。来源记录为 2026-09-04；`app/src/main/assets/bilibili-initial.json` 中的 `syncedAt=0` 明确表示不是自动同步成功。App 会显示“初始目录”和同步失败状态，而不是用这三条冒充实时目录。视频里作者自己朗读评论属于视频画面/音轨内容，和应用评论区是两回事；本应用不对原视频内容做删改。

**实际播放已验证一条：** API 31 模拟器中，汗疱疹视频画面持续推进，在 01:50 暂停约 15 秒保持静止，恢复并拖动至 02:30 后继续播放。另两条尚未逐条实播，声音输出未听取验收。平板订阅目录已检查；电视只检查了本次顶部布局，不能据此认定 TCL 真机兼容。详细记录见 `qa/online-notes.md`。

这版先让设备自己维护 JSON 目录，**没有部署电脑常驻后台或云端管理页面**，因此不要求 Mac 常开，也不需要向公网暴露 NAS。尚无成功同步目录时读取打包的初始 JSON；成功后保存到应用私有 SharedPreferences 的 `bili.feed` 字段，包含 schema、uid、syncedAt 和 videos（bvid、uid、title、author、published、duration）。只在完整验证后替换上次成功目录；错误另存，不把失败当作空目录覆盖。

- 同步范围：若接口可用，则同步指定作者最近 30 条投稿，每次替换这个窗口，不是完整历史归档。窗口外影片不再显示，收藏和进度不会扩大白名单。当前只交付初始 3 条，不声称已取得最近 30 条。
- 自动更新：启动/回到应用时检查，前台每 15 分钟检查，后台通过 WorkManager 按 15 分钟周期申请有网络时执行。系统省电、强行停止等可能延后任务，不承诺实时推送。手动请求最少间隔一分钟；遇到平台拒绝停止本次请求，不做绕过或密集重试。
- 播放校验：视频必须在当前允许目录内，播放前再核对视频详情里的作者 UID、视频状态和付费标记。只尝试匿名可访问内容，不处理登录、会员、充电专属或受限预览。
- 纯播放器：使用原生 Media3，按需获取 H.264 视频和 AAC 音轨并合并播放，或使用返回的单段流。没有网页播放器、WebView、评论或弹幕请求；播完停止，不跳到推荐视频。播放地址不持久保存，只使用正常播放缓冲，不做整部下载归档。
- 地址限制：HTTPS，固定 B 站 API 主机，媒体仅允许 `*.bilivideo.com` / `*.bilivideo.cn` 的标准 HTTPS 端口；每一跳媒体重定向都重新检查。会从同一播放接口提供的主/备地址中选择符合限制的地址；未支持的 CDN、格式或清晰度会报错，不转交外部应用。
- 当前能力边界：优先公开 480p 或更低 H.264；多分 P 视频只播放第一 P。封面沿用通用插画，并非真实视频封面。Wi-Fi 和移动网络均会产生正常音视频流量费用。
- 内容边界：自动允许这个作者的新投稿不等于家长逐条审核，视频内自带的商业内容也不会被自动去除。这只是应用内范围限制，不是整台平板的设备级儿童管控。

参考 [RSSHub 的投稿目录设计](https://github.com/DIYgod/RSSHub/blob/master/lib/routes/bilibili/video.ts) 和 [Bilby 的订阅及原生播放思路](https://github.com/NihilDigit/bilby)。本次新增代码为独立实现，未复制其完整客户端或引入账号/指纹模拟流程；这些社区方案不代表平台对第三方播放提供稳定授权或服务保证。

如果正常访问仍持续被平台拒绝，需要先确认可用的合规访问/授权方式，再决定服务端集中同步或其它来源；本版不把这个待解决问题掩盖成已完成。

## 在这台 Mac 上使用

- 双击 `启动小小影院.command`：启动专用 Android 模拟器、安装现有原型并打开。
- 双击 `更新并运行.command`：重新编译后安装运行，正常更新保留连接设置和观看进度。
- 首次启动时，macOS 可能询问“终端”访问“文稿”文件夹，因为项目保存在这里；请允许此项访问。无需授予完全磁盘访问权限。如果暂未允许，可先在已有模拟器中体验，稍后再运行脚本。
- 项目可以用 `/Applications/Android Studio.app` 打开。SDK：`/Users/shawn/Library/Android/sdk`。
- Java 17 使用 Homebrew 的项目指定路径；没有更改 shell 配置或其他项目的默认 Java。换电脑时应修改 `gradle.properties` 的 `org.gradle.java.home`，以及 `tools/env.sh`。
- 模拟器是通用 Android ARM64 平板，不是 HarmonyOS 模拟器，也不是 TCL 固件模拟器。电视布局按钮仅验证交互布局，不能证明真实 TCL 兼容。
- 默认模拟器是 `KidCinema_Tablet_12`（Android 12 / API 31）。旧的 `KidCinema_Tablet`（Android 11）保留作兼容排查，但不用于日常演示：该 ARM64 镜像复现了[已记录的暂停解码错误](https://github.com/google/ExoPlayer/issues/10576)。启动脚本固定使用新版，不改变真机的解码器选择。

终端运行：

```bash
source tools/env.sh
./gradlew assembleDebug testDebugUnitTest
bash tools/run.sh --build
```

APK 在 `app/build/outputs/apk/debug/app-debug.apk`。这是本地调试签名的原型，不是上架或正式发布版。后续正式分发需固定并妥善保存签名密钥；更换签名不能直接覆盖旧包。

## 原型包含

- 中文影片卡片、影片详情、喜欢、继续观看、当前目录刷新与子文件夹导航。
- 可真正播放的 18 秒本地原创 H.264 演示视频，四张不同封面共用这段视频，界面明确说明；视频无音轨。
- 播放、暂停、进度拖动、前后跳转；离开页面或进入后台保存进度并释放播放器。
- 平板/电视/自动模式。电视使用方向键、确认和返回，焦点显示金色边框。
- 按用户指定使用爱心萌可主题的生成式角色图标与电视入口图，应用名仍为“小小影院”。这是家庭自用原型素材，不是官方授权标识；若以后公开分发，应另行确认角色授权或换成原创角色。
- 按用户要求不设置儿童密码或家长 PIN；“播放设置”直接打开。SMB 共享本身若需要账号密码，仍需填写连接凭据，并使用 Android Keystore AES-GCM 加密保存，关闭系统备份及设备迁移。
- SMB2/3 读取，支持账号密码、指定共享与相对根目录；不实现写入、删除或其他共享的浏览界面。
- 所有列目录、开文件和播放都经过相对路径检查；拒绝父目录穿越、绝对地址、替代数据流及已识别的符号链接/重解析点。

## 连接华为家庭存储

1. 确认平板/电视与存储处于可互访的同一家庭局域网，不能是隔离的访客网络。
2. 在智慧生活的家庭存储“网络邻居”中查看局域网 IP、共享名及访问凭据。建议在路由器为存储保留固定 IP。
3. 点击“播放设置”，无需任何儿童密码或 PIN。
4. 填入 IP、SMB 端口（通常 445）、共享名（以实机为准）、允许访问的相对目录。例如共享为 `家庭共享`，目录为 `女儿视频`。不要在目录栏填 `smb://` 地址；留空代表允许整个所选共享。
5. 点击“测试此目录的读取”。测试只验证当前目录可读，不验证其他目录不可读。
6. 关闭“使用本地演示内容”，保存。

请使用存储端已经限制范围的共享凭据，尽量只读。应用界面隐藏其他内容不等于服务器权限隔离；华为设备是否支持所需的单目录/只读粒度，仍须在实机确认。不要配置匿名开放的私人共享，也不要使用全盘管理员凭据。

目录固定为设置中指定的范围，没有儿童密码；任何能进入设置的人都可以修改连接和目录。请勿清除已有正式设备数据来运行测试。

## 代码位置

- `MainActivity.java`：首页、卡片、家长配置和两种布局。
- `PlayerActivity.java`：Media3 播放和生命周期。
- `SmbLibrary.java` / `SmbDataSource.java`：只读 SMB 浏览与随机位置读取。
- `PathPolicy.java`：统一目录边界。
- `AppStore.java`：配置加密、进度和喜欢。
- `ArtView.java`：本地程序绘制的封面，不联网抓取图片。
- `tools/generate-demo.swift`：原创演示视频生成脚本。

第三方组件：AndroidX Media3、SMBJ（Apache-2.0）、Bouncy Castle、SLF4J，以及仅用于测试的 Impacket。依赖版本固定在构建文件中；正式交付前应再次核验许可证和安全更新。
