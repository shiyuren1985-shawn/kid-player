# 思思影院：网上的 UP 主名单

将 `sisi-creators.example.json` 放到你自己的 VPS/静态站点上，通过普通 HTTPS GET 返回 JSON 即可。当前示例只有已指定的画渣花小烙；没有替你添加其他真实作者，也未部署到 VPS。

在 App 的“播放设置 → 管理 UP 主名单 → 云端名单”填入文件的 HTTPS 地址，点“读取并使用云端名单”。地址和整份有效名单一起保存；之后在启动/回前台时检查，前台约15分钟检查，后台由系统调度。无需登录B站或导入账号 Cookie。你尚未提供实际地址，因此当前保留原来一个作者作为初始名单。

## 文件格式

- `schema` 必须为数字 `1`。
- `creators` 是数组，排列顺序就是头像顺序；每行是一个对象。
- `uid` 是正整数或数字字符串。建议字符串，避免某些编辑工具对大整数四舍五入。
- `name` 可选，仅是名单的显示名称；取得平台作者资料后会显示平台昵称和头像，身份始终由 UID 决定。
- `enabled` 可选，默认 `true`。改为 `false` 即停用。
- 不要在文件中提供媒体地址、账号、密码、Cookie 或其他凭据。

添加作者：在数组中加入其 UID。停止展示：删除对应行或设 `enabled: false`。`creators: []` 是有效的空名单，会停用全部作者。停用/移除会隐藏影片并拒绝新播放；在播作者被停用时也会退出播放。收藏和观看记录保留在本机。

整个文件必须校验成功后才替换名单；JSON错误、重复/无效UID、下载失败等不会应用部分名单，会保留上次成功名单。网络断开期间无法获知云端新变更，因此仍使用上次有效名单。当前上限100个作者、256 KiB；超限报错并保留原名单，不静默截断。

只接受 HTTPS，重定向也必须继续使用 HTTPS。链接应直接返回JSON，不能是网盘预览页、登录页面或HTML。推荐服务器 Content-Type 为 `application/json; charset=utf-8`，Cache-Control 使用 `no-cache` 或较短时间，避免长缓存延迟更新。应通过原子替换发布文件，避免App读到写了一半的内容。本版不支持需要登录或自定义认证头的文件地址。

## 每位作者的视频目录

每个作者分别保存目录、同步时间、错误、收藏和进度。点头像只显示该作者的影片。视频范围仍为其公开合集中的最新30条；未加入合集的投稿可能遗漏。如果作者没有受支持的公开合集，不能保证出现影片；平台拒绝时不会绕过，也不会以其它作者内容填充。选中作者优先在前台检查，后台按名单顺序在有限运行时间内轮流检查，作者多时可能延后。

作者身份、公开状态、付费标记以及播放地址白名单仍在播放前检查。缩略图和头像只从平台图片域名读取，失败时显示占位图，不影响目录浏览。

## 可选本机方式

“本机管理”是独立模式，可以填写UID、核对平台资料后添加，选择启用/移除。云端模式不能使用本机增删接口；两份名单分开保存，不合并。切回云端会重新使用云端名单。名单管理的修改立即生效，不由外层播放设置的“取消”撤销。

## 已验证与待接入

配置解析、增删停用、空名单、格式失败保留、两种来源隔离及作者数据隔离使用注入的测试JSON验证。实际VPS域名、TLS、缓存策略、远程文件发布→设备自动读取的完整路径，要等你提供文件地址后验收；不能把模拟响应测试称为已验证你的服务器。
