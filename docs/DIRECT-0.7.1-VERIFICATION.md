## 真实访问与播放

1. 旧原生 HTTP 请求在同一专用模拟器反复返回 412；实际 UA、来源头及降频对照见 REQUEST-412-DIAGNOSIS.md。HTTP 200 / code=-352 仍按失败处理。
2. 正常 Chrome 匿名移动网页会话自然取得 buvid3/buvid4 等 Cookie。使用当前投稿参数并通过页面 fetch，投稿 API 返回 code=0；页大小 30，后续两页分别 30 和 26，总数 86。未借用个人浏览器或账号凭据。
3. APK 改用自己独立的匿名 WebView 会话：访问正常官方移动首页，由网站自然建立会话，再在该上下文 fetch API。未注入随机设备指纹、未复制 Chrome Cookie；孩子界面没有浏览器或登录页面。元数据仍经过业务码、作者 UID、BVID、分页完整性检查，原生播放器的作者/公开权限和视频域名检查保留。
4. 最终 APK 真网验收 run-20260907-190444，OK 2 tests（22.375 秒）：UID 3546918961547843 识别为混子哥边画边讲，完整目录 86 条，立即重试进入 COOLDOWN。实际 PlayerActivity 播放 BV1D3th6VEnR：进度 5213ms、视频解码渲染 159 帧、音频渲染 265 个缓冲区，无播放器错误。未进行真人听感或整片检查。
5. 前轮候选包独立验证也通过：run-20260907-185749 全部 86 条；run-20260907-185907 实际播放 5145ms、157 帧、243 音频缓冲区。最终包在重启测试进程后再次通过，不能据此承诺长期或所有设备均不再受限。

## 同步行为

- 元数据请求串行，结束后至少间隔 1.2 秒；WebView fetch 15 秒终止，会话初始化和单次请求各有 25 秒等待上限，响应流最大 2,000,000 字节。请求结果按独立槽位隔离，取消时终止对应请求，不将前一请求结果交给下一请求。
- 首次全量每轮最多 5 页（150 条），已读取数据与续传进度一同保存。继续前检查头页、总数与上一页边界；不匹配则重新开始。进度最长复用 6 小时。
- 最近 24 小时已完整核对的目录，只有新增数量和旧目录连续前缀衔接一致时采用增量合并。到期后的下一次同步重新做全量；不等同于保证每天定时准点执行。完整核对前保留旧条目，完整后才移除已删除条目。
- 平台未提供本轮快照标识，同数目的中间条目在续传期间发生变化仍可能延后到下一次完整核对发现。播放时另行即时核验作者和公开权限。
- 合集成员在元数据不变且 24 小时内复用，普通手动刷新同样适用。
- HTTP 403/412/429，业务 -352/-401/-403/-412/-509 独立归为受限；30 分钟、2 小时、6 小时、12 小时递增冷却在应用偏好中持久保存，并覆盖所有作者的同步。手动刷新不能绕过。该时长是应用策略，不是平台恢复承诺。普通超时不写入风控冷却。
- 投稿完整而合集/资料请求受限时仍保留完整投稿，但停止本轮并记录冷却，不能因为可选请求而继续撞风控。成功完整同步后清除风险级别。
- 保留目录、收藏、观看记录和本地/SMB 模式；没有转为 NAS 下载。已开始的播放不会因目录同步冷却而主动中断。
